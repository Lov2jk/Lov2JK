# Catalogue shopping: owner guide

## Add a design

Open Catalogues in Pages CMS. Edit a collection and add an image row under Catalogue products and images. Enter its Product Code and name, then save. Add another row with the same code for a second photo.

For an existing shop product, turn on **Link to shop product** and use its exact Product Code. Price, sizes, colours and stock come from the shop. Quick price update and Quick stock update remain the places to change those values. The catalogue price field is ignored for linked products.

For a catalogue-only design, leave the link off. Enter the price and comma-separated exact sizes (for example `3Y, 4Y, 5Y`) and colours. Set availability to sold-out when needed. Age ranges request a size from the customer and require confirmation; they are not presented as exact stock by size.

## Hide or remove

Turn off **Show this image** for temporary removal. Hide all rows of a Product Code to hide the whole design. Remove image rows to remove a design permanently from a collection. Turn off **Show catalogue on website** to hide the whole collection. Linked shop products also disappear when the underlying shop product is hidden or deleted. Original uploaded photos are not deleted.

## Customer ordering

Customers select size, colour and quantity, then add designs to the catalogue bag. They can collect designs across catalogues and remove items or change quantities. The catalogue bag is separate from the existing shop bag and clearly labelled. No login is needed.

Before opening WhatsApp, the website reloads prices and availability. Customers must review changed prices. The message includes codes, image links, choices, quantities, subtotal and an enquiry reference. Shipping and final stock require confirmation. Opening WhatsApp is not a sale or a stock reservation; the customer still presses Send. Bag contents remain on their device until removed.

Save changes in Pages CMS and wait for the GitHub Pages deployment to finish. Refresh the website to check them. No customer records or backend access are exposed by this feature.
